# Framework Mapping Notes

Mappings are **indicative cross-references**, not a certification checklist or compliance determination.

## NIST CSF 2.0
High-level categories referenced include GV (Govern), ID.AM / ID.RA (asset and risk understanding), PR.AA / PR.AT / PR.DS / PR.PS / PR.IR (access, awareness, data, platform security and resilience), DE.CM / DE.AE (monitoring and analysis), RS.MA / RS.AN / RS.CO / RS.MI (incident management, analysis, communication and mitigation), and RC.RP / RC.CO (recovery).

## CIS Critical Security Controls v8.1
Potentially relevant control groups include 1 asset inventory, 2 software inventory, 3 data protection, 4 secure configuration, 5 account management, 6 access control, 7 vulnerability management, 8 audit logging, 9 email/browser protections, 10 malware defenses, 11 data recovery, 12 network infrastructure, 13 network monitoring, 14 awareness, 15 service providers, 16 application software security, and 17 incident response. A group-level reference does not mean every safeguard applies or is satisfied.

## SOC 2 Trust Services Criteria
SOC 2 is an attestation, not a certification. Illustrative references include CC1–CC4 (control environment, communication, risk assessment and monitoring), CC5 (control activities), CC6 (access), CC7 (system operations and incident response), CC8 (change management), CC9 (risk mitigation and third parties), and A1 where Availability is in scope. Applicability depends on the system boundary, service commitments, selected categories, and auditor interpretation.

For a real program, maintain exact criterion identifiers, control owner, evidence, test procedure, frequency, result, and remediation. Validate against current authoritative framework material.
