# Contributing

1. Use unique risk IDs (`R-##`) and avoid duplicate scenarios.
2. Describe each risk as cause / event / consequence.
3. Cite evidence before claiming a control is implemented or tested.
4. Keep proposed actions separate from existing controls.
5. Explain score changes in review notes or commit messages.
6. Do not claim compliance, certification, audit success, or effectiveness without evidence.
7. Validate framework mappings against current authoritative documentation.
